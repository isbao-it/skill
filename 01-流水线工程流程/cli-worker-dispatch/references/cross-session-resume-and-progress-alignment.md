# 跨会话接手：按文件对齐进度，再继续（2026-09-19 实测）

## 触发

- 用户说「**我在别的会话里推进了进度**，你按文件对齐后继续」/换个会话接手 / 上下文被压缩后回来。
- 原则：**文件是唯一事实来源**，不是你的记忆、也不是对方会话里的叙述。

## 步骤（照顺序做，别跳）

1. **时间锚 + 仓库盘点**（一条命令批下来）
   ```bash
   date; git log --oneline -15; git branch; git status --short
   ls -la --time-style=+%m-%d_%H:%M project/outputs/<卡>/         # 另一会话留下的产出/派工单/审计文档
   ls project/outputs/待审核/<卡>/                                 # 已交回未合入的 run
   ```
   从**文件时间戳**能直接读出对方做到哪一步（本次：22:17→23:05 一串 `R0x派工单`、次日 11:05 一条失败日志）。

2. **进程盘点：先确认没有 worker 在跑**（避免双派、避免误杀）
   ```bash
   powershell -NoProfile -Command "Get-CimInstance Win32_Process -Filter \"name='node.exe' or name='codex.exe'\" | ForEach-Object { \$_.ProcessId.ToString() + ' | ' + \$_.CommandLine }"
   ```
   ⚠️ **区分身份**：`@modelcontextprotocol/server-*`、`npx playwright`、`codex app-server` 是 **Hermes 桌面/Codex 客户端自身**的进程，
   **不是**我们派的工人；我们的工人是命令行里带 `codex exec …` 的进程。**清孤儿只能按 PID 定点杀，禁按名字批量杀**。

3. **读对方留下的审计/诊断文档**（它们通常已含"真因 + 待办 + 未验证"）：
   `project/outputs/<卡>/*诊断*.md`、`*审核*.md`、`R0x派工单*.md`。不要重新摸索 —— 重摸一遍就是白烧一轮额度。

4. **自己实测当前基线**（关键）：对方文档里的数字是**当时**的，不是现状。
   亲自跑一次定向（+ 覆盖率），以实测为准再决定下一步。本次实测 = `172 passed / 2 failed`，
   而文档叙述停在一个更早的状态；用错基线会让派工单的靶子偏掉。

5. **对齐「进度 + skill」两件事**（用户明确要求的动作）：
   - 进度：把对方的发现落成**快照条目**（审计结论、环境事故、待用户裁定项、下一张卡入口），
     卡状态按实测改写（没合入就别写成"已完成"）；
   - skill：把**可复用**的教训写进对应 reference（本次固化：测试规格保真/覆盖率客观化、宿主崩溃识别、本条跨会话接手）。
   提交时只 add 相关路径，**不要**把并行线产物（如用户自己维护的实时解释/学习笔记、素材目录）混进 commit。

6. **继续干活**：**优先复用对方已写好的派工单文件**（`R0x派工单*.md`），
   只做两件修改：(a) run id 顺延；(b) 用**你刚实测的数字**刷新里面的靶子（覆盖率/失败清单）。
   自己从头重写派工单 = 白烧一大轮额度 + 丢失对方的精确诊断。

## 约定（让下次接手更省）

- 派工单**落成项目内文件**：`project/outputs/<卡>/R0x派工单.md`、待发的写 `R0x派工单待发.md`，
  正文自带"用法"命令行 → 中断/换会话后可**原样重派**，不必重建上下文。
- 决策留痕落 `project/decisions/decision_<卡>_<主题>.md`，并在卡面/裁决同步引用，接手时一眼可见"用户拍过什么板"。
