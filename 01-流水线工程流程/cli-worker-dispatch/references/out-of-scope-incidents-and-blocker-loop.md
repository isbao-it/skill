# 越界事故、阻断项闭环与终端/并行写入的坑

来源：2026-09-14/15 连续三张卡（02a/02b/03）的实战。SKILL.md 已覆盖派工骨架、失败模式判读、
验收四件事；本文件只记 SKILL.md 里还没有的部分。

## 一、越界不只是"写入"：删除/移动同样要显式禁止

派题里只写「除这些文件外不得写入任何文件」时，工人仍会**自行删除**它认为"多余"的文件
（临时目录、废弃脚本、以及**没进 git 的待审交付物**）。实测损失：3 份从未入库的交付文档被清掉。

派题第 4 段应写成：

> 除上述文件外，**不得写入、删除或移动任何文件** —— 含"顺手"更新项目文档/实时解释/学习笔记/
> 模块文档，也含"顺手清理临时目录、废弃文件、`.coverage`、旧日志"。

事故处理与恢复（脚本、搜全盘顺序、字节数比对、放回原位、立刻入库）见
`delegated-output-verification/references/card-and-doc-deliverable-review.md` 与
`delegated-output-verification/scripts/recover_worker_deleted_files.py`。

另一条配套：**任务卡/模板里可能还留着自相矛盾的旧样板句**（例如卡面 §2.1 仍写"执行者应更新
`项目实时解释.md`"，而你刚在派题里禁止了这件事）。同步规则变更时回头扫一遍卡面，
否则工人面对两条互斥指令怎么选都是错。

## 二、阻断项闭环：工人带问题回来时怎么办

工人遇到**现有材料无法唯一确定**的东西（缺字面名、跨卡顺序、未定义枚举、DTO 承载不足、
"当前版本"选择口径）时，正确产出是把它写成卡内「执行前先报告等批准」项，**禁止自造值/建空壳**。
调用方（Hermes）的固定闭环：

1. 把阻断项汇总成**人话表格**：问题 / 需裁决什么 / 我的推荐 + WHY（一次交决策者，别逐条问）
2. **开架构师续会**（复用已存 session，不重开）：要求逐项给"已核实/不成立 + 依据（引用真实字段/表列）"、
   可直接落进卡面的措辞、对已合入 schema 的影响、会牵动哪些既有断言
3. **会后验收**：重算关键数字（新增/删除/净增、哈希重算、冲突检查），不看自报
4. 批准后：**程序化并入设计文档**（按标题抽块 → 按锚点插入 → 幂等可重复执行 → 打印插入位置与行数变化核对）
5. **留痕三件套**：裁决稿状态改「✅ 已批准（日期 + 批准了什么）」、`decisions/verdict_<卡>.md` 一页索引、
   会议纪要追加本轮（session id / 议题 / 结论 / 待办）
6. 派工人按裁决的"逐节修改指令"同步卡面 → **逐行对账初审** → 终审三块速读 → 才派执行

拆分建议（"这卡太大，建议拆 a/b"）由工人写成待批项；裁决要明确"两批各自的 GWT 归属与关闭条件"，
并写死**最终口径不变**（端口数/方法数/GWT 数统一关闭）、"前一阶段完成 ≠ 整卡完成"。

## 三、终端长命令被 harness 拦（不是命令本身有问题）

超长内联命令（heredoc + 大量 `;`/`&&` + 多段管道、上千字符单行）会被硬拦：

```
BLOCKED (hardline): command parser limit or malformed executable payload.
Your command was saved to <...>\blocked-scripts\blocked-*.sh
```

**别重试同一条**。把脚本用 `write_file` 落成 `.py`（放 `$LOCALAPPDATA/Temp` 之类非仓库目录），
再 `terminal` 跑一行 `.venv/Scripts/python.exe "<路径>"`；只读检查类命令拆成 2–3 条中等长度调用，
比一条巨长命令更稳、更好定位失败。含未加引号的 `&` 也可能被当成后台符拦下。

## 四、并行写入者：同一仓库可能有多条会话在动

现象：`git log` 里出现你没提交的 commit；patch 结果带
`modified by sibling subagent '…' but this agent never read it`；文件 mtime 变了但没人承认动过。

处置：

- **归因留余地**：出现兄弟会话时，不要把改动一口咬定是"工人越界"（本次曾错误归因，事后更正）
- **改共享文档前先看 uncommitted diff**，把你的修改叠在对方的版本上，而不是从自己记忆里的版本重写
- 自己写的 `.gitignore`/配置与对方重复时，清理重复段再提交
- 报告里**列出未提交的并行改动**，让用户知道有第二条线

## 五、决策类回复的读法（用户侧习惯，影响派工节奏）

- 短回复「继续 / 下一步吧 / 开始吧 / 🟢」＝ 按你给出的**推荐项**直接推进，不必再确认一遍
- 但**涉及已合入 schema、删除、不可逆操作**时，回复开头写明"我按 X 执行"+ 一句"随时喊停"
- 用户说"我先看一眼再定" → 给**行号级阅读地图**（看哪节 → 行范围 → 里面是什么，先看项排最前）
  + `open_preview` 打开主文件 + 点名 2–3 处"我核得最狠的地方"请他重点看
- 决策要一次给全：小表格（事项 / 我的建议 / WHY）+ 推荐项排第一的选择项，别把选项埋进正文
