# 运行中断与冻结契约冲突的收尾四则（2026-09-20 卡12f/12e 实测）

> 归属：`cli-worker-dispatch` 的 SKILL.md「三、失败模式」「五、节奏与纪律」「六、常见坑」补遗。
> 四则都属同一类：**派工已经在跑了，事情却因"环境/框架/用户改判"偏离卡面**，这时调用方怎么收尾。

## 1. `0xC0000142` / `-1073741502` = 宿主「创建子进程」能力损坏（transient，不是代码/额度/卡面问题）

**症状**（派工 stdout 尾部，常在跑到中段时出现）：

```
orchestrator_helper_exit_nonzero: setup helper exited with status Some(-1073741502)
hook: PreToolUse Failed
```
此后宿主里**任何**命令都起不来（含 PowerShell/cmd）。

**判读**：这是执行宿主的进程创建能力坏了，**不是**卡面写错、不是额度、不是代码问题。
本会话复发 **2 次**（卡12 R07、卡12f R01，相隔一天）→ 属会自愈的环境故障，**不要**写成"某工具不可用"的长期结论。

**工人的正确行为**（实测两次都如此）：同因失败 2 次即熔断，自报 `..._FAIL`，**零文件写入、零伪造**。
调用方必须**核磁盘**验证：`git status` 应干净、交付目录应为空 —— 一致才说明"上一轮零损失"。

**处置顺序**：

1. **别改派工单、别怀疑代码、别重跑前面的分析**；
2. **先探活**（几分钟、极便宜）：
   ```bash
   timeout 90 codex exec -m <model> -c model_reasoning_effort="low" \
     --skip-git-repo-check -C <项目根> "只回复两个字：正常"
   ```
   返回「正常」＝已恢复；
3. **原样重派同一份派工单**（run_id 不变 —— 上一轮零产出）；派工单头部加一行：
   > 上一轮同单因「命令执行器无法创建进程（0xC0000142）」被熔断中断，**未写任何文件、未运行任何测试**。宿主已恢复。请正常执行本单：快速重读规格后**直接从写红测开始**。
   （省掉一轮重复通读）；
4. **判损**：只损失上一轮"读规格"的 token，**不损失产出**（worker 增量落盘）。所以**永远不要**因为这类中断重写卡面或加派分析轮。

宿主侧的修复动作（重启 Codex 宿主/桌面应用）属**用户侧**；调用方只负责探活 + 原样重派。

## 2. 卡面冻结的「次序/优先级」与框架天然行为冲突 → 派工单必须留**逃生口**

实例：卡面把处理顺序冻结为「body 超限 413 → JSON 语法 422 → CSRF 403 → 字段/路径 422 → 业务」，
而 FastAPI 的依赖解析/body 校验天然顺序**未必**凑得出这个次序。
不放逃生口，工人只剩两条坏路：**硬凑**（可能塞 hack 或悄悄放宽校验）或**白停一轮**。

**写法（逐字可抄）**：

> 若框架天然顺序与上面冻结顺序无法同时满足：**不要硬凑、不要放宽 <安全校验>**；以**实测顺序**为准，
> 在交付记录里写明「实测顺序 vs 卡面顺序的差异 + 原因」，并保证「<安全意图>」（如：**CSRF 校验失败时不得读取或处理请求体内容**）不变。

**通用化**：任何卡面冻结的「次序 / 优先级 / 谁先谁后」类约束，派工单都要同时给
**「以实测为准 + 安全意图不放宽 + 差异写进交付记录」**三件套。

## 3. 用户中途喊停 → 写「停机点」到进度文件（含恢复入口）

触发语形：「这个卡派完就先算不做了」「先不要派，等我说派再派」。
**已在跑的进程不要 kill** —— 让它跑完（产出是增量落盘的），只是"**跑完仅落档提交，不做后续**"。

停机点必须写进进度文件（本项目 `project/outputs/进度快照_*.md`），四项缺一不可：

1. 停止时**正在跑什么**（哪张卡 / 哪个进程号）；
2. **不再做什么**（不初审 / 不派后续的哪几张）；
3. **恢复入口**（产出在哪个目录、下一步是初审还是派执行、上游前提是否已满足）；
4. **已冻结的卡号清单**。

为什么值得写：换会话/隔天接手时，最贵的是"**该不该继续**"这个判断 —— 快照里有停机点，就不会误派、也不会漏掉已付费的产出。

## 4. 用户改判一个数值 → 立刻查「还有几处同义常量」

实例：密码下限由架构师推荐的 15 被用户改判为 **8** → 至少**三处**必须同口径：
**CLI 脚本护栏 / HTTP 注册 / HTTP 登录（只限上限）**；而当时另一张**正在跑**的卡（12c）已把脚本护栏写死成 `12～1024`。

做法：

- (a) 改判**立刻落卡 + 在裁决里加「用户拍板」节**（写明改判值与理由原文）；
- (b) **主动列出全部同义位置**（本会话：脚本护栏、HTTP 注册、HTTP 登录上限、**以及上一张卡已合入/正在写的脚本常量**）；
- (c) 卡面明写「**由哪一张卡负责统一**」，并把被改文件加进那张卡的写入白名单；
- (d) 若某处属于**正在执行中**的卡：**不要去改它的卡面**（工人已读过，改了也不生效且会造成漂移），
  交给**下一张卡**收敛，并在下一张卡里明写「该常量被本卡取代」。
