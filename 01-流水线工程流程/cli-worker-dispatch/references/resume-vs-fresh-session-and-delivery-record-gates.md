# resume vs 新会话（实测结论）+ 交付记录合规与验收门禁（2026-09-18）

> **本文取代** `quota-probe-and-caller-economy-2026-09-18.md` 里「出卡会话 resume 续执行仍是待实测项」那条：
> A/B 已做完，数字在下面。该条当时的禁令（"没拿到对照数字前不许写成推荐做法"）现已由实测解除。

## 一、resume 续执行 vs 新开会话：**不省反贵 ≈2 倍**（实测）

| 会话 | tokens | 活的大小 |
|---|---|---|
| 出卡（新会话，`effort=high`：裁决 + 双卡） | 136,033 | 中 |
| **同会话 `resume` 接着执行** | **334,415** | 1 新模块 + 2 入口 + 6 组测试 |
| 执行（**新会话**）对照 | **166,624** | 6 文件 + 18 用例（**更大的活**）|
| 返工（新会话）对照 ×2 | 83,738 / 98,630 | 各修 1 处 |

**为什么没省**（实测观察，不是推测）：

1. `resume` 每轮重放的是**出卡会话的完整上下文**（架构探索 + 双卡 + 来源核查，约 13.6 万基线）——
   这正是"每轮重放"最贵的地方；
2. 执行段该做的事**一件没少**：仍要重读最新卡面 / 裁决 / schema / 输入白名单文件；
3. 轮数没降（覆盖率反复迭代，交付目录里躺着多份 `*-failed.log`）；
4. 返工也没减少（交付记录格式仍需主代理归一，见第二节）。

**处置（写进纪律）**：worker 一律**新会话 + 紧派题**；`resume` 只剩一个用途 ——
**抢救被中断/撞限的会话**（保住已落盘上下文），不作为省额度手段。
出卡产出的「双卡 + 裁决」本身就是下一轮最短输入，比带着出卡上下文 resume 便宜得多。

**记账法**：`grep -a -A1 "tokens used" <运行.log>`；效果会话说到底看 **tokens + 轮数 + 是否返工** 三个数，
固定留 `project/outputs/<NN>/额度实验_*.md`（假设 → 本次数字 → 对照基准 → 结论）。

## 二、交付记录（`summary.json`）的 schema 门禁：**几乎每轮都会被工人写错**

工人很擅长**把活干对**、很不擅长**把记录写合规**。同一项目连撞三次：
`metrics` 缺 `source`（WARN）→ 又是 `source`（WARN）→ 这次 **24 ERROR**（枚举写错、必填留空）。

高频违规清单（验收前一并核）：

| 字段 | 工人常写成 | schema 要的 |
|---|---|---|
| `tests[].result` | `passed` / `failed` | `pass` / `fail` / `not_run` / `error` |
| `tests[].phase` | 空串 | 枚举：`red`/`targeted`/`regression`/`coverage`/`lint`/`performance` |
| `tests[].cmd` | 空串 | **逐字可复现的命令**（必填） |
| `tests[].evidence_path` | 缺失 | 只要 `result` 声称「已运行」就必须给，否则 WARN |
| 覆盖率条目 | 只写 pass | 还要 `coverage_percent` + `coverage_threshold` |
| `files[].change` | `null` | `added` / `modified` / `deleted` |
| `metrics` | `null` | 至少给 `source`（"来源不明的读数不要写"） |

**归一法（主代理做，属验收记账，不是改代码）**：

1. 先**自己复跑**，拿到权威数字（定向/覆盖率/lint/全量）—— 归一时只填**自己核实过的**值；
2. 机器改写枚举与必填项，`note` 里写明「Hermes 初审归一：原记录 phase/cmd 为空、result 写作 passed/failed」；
3. **把自己复跑的原始日志拷进交付 `details/`**（`hermes-directed.log`、`hermes-coverage-*.log`、
   `hermes-ruff.log`、`hermes-full-regression.log`）并作为**独立条目**加进 `tests[]`，
   `evidence_path` 指向真日志 —— 不伪造工人的命令，也不留无证据的自报；
4. 复跑 `python project/templates/validate_summary.py <summary.json>`，**判据是 0 ERROR 且 0 WARN**。

派工单里直接把这些枚举字面值 + 必填项钉进卡，能省下一整轮返工。

## 三、覆盖率门禁：`--cov-fail-under` 判的是**总和**，不是每模块

卡面要求「A/B/C 三模块**各** ≥80%」时，一条命令跑三个 `--cov=` + 一个 `--cov-fail-under=80`
**只**保证三者平均达标 → 某模块 60% 也能绿。**必须每模块各跑一次**（各自 `--cov-fail-under` + 各自日志）。
初审看到"合跑 + 阈值"就要当场改命令，别等验收。

## 四、初审必做：卡面 ≠ 权威契约，要拿**冻结文本**逐条对矛盾

教训（实测）：给一张卡派了"返工"，让它实现「加载成功但首次计算失败 → 换候选回退」，
而架构里**早已冻结**「转写期失败不再新建回退模型」—— 卡面的"四态可观察"其实**靠初始化期尝试就能满足**。
根因是**环境**（缺 cuBLAS/cuDNN），本该修环境而不是改契约；结果代码与冻结架构偏离，事后还得补一次裁决把它合法化。

**判据（派工/返工前花两分钟）**：

- 先问「这是**环境因**还是**契约因**」：环境因 → 修环境（装库/配 PATH）+ 记录前置条件；契约因才动代码；
- 动代码前，把卡面要求与权威文档（架构/裁决/端口冻结段）**逐句对**，冲突就先出裁决，别先改代码；
- 新契约落地后，把原句改成「本句经 §X.Y 修订：…」并留指针，避免下一个人再撞同一处。

## 五、出卡姿势（省一轮）：**裁决 + 双卡在同一会话产出**

对照实测：某卡"先出卡 → 用户审 → 才发现六项缺口 → 补裁决 → 再回写双卡"= **多烧一轮同步**；
另一卡让架构师在同一会话里**先出裁决（含方案对比与依据）、再按裁决写双卡 + 架构补丁正文**，
一次过审、零返工。派出卡单时就写明这三件产出，并要求双卡字符上限（执行卡 ≤8,000 / 测试卡 ≤6,000 /
合计 ≤14,000、行为组 ≤8）——超限即驳回。
