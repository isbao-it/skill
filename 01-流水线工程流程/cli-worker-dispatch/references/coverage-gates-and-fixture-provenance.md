# 覆盖率门禁的两类真缺口：整层未测 与 夹具来源造错（2026-09-18 卡11 R03→R05 实测）

派工单里写了覆盖率门槛，工人交回"定向全绿"但覆盖率不达标 —— 先分清是**门槛不可达**（写法问题，见
`linkage-gates-and-diagnose-before-dispatch.md` §2）还是**测试结构问题**（少了整层覆盖）。本文是后者。

## 1. 硬信号：`Module X was never imported`

coverage 原始日志里出现

```
CoverageWarning: Module app.services.<x> was never imported. (module-not-imported)
```

⇒ **该模块一行都没被执行**，对应覆盖率必然 0%。这不是"覆盖率略低"，是**整层没有测试**。

实测形态（卡11）：8 组 GWT 全绿、定向 16 passed，但 `app/services/creative.py` 变更语句 **111/111 未覆盖**，
于是业务层合计只有 50% —— 因为 GWT 全在 **agent 层**（纯函数式）和**仓储层**（真 SQLite）被证明，
而**编排服务层**（首轮建档、幂等回放、双检 CAS、配额预占/结算、失败 0 写、竞态优先级）没有任何测试导入过它。

**判读**：这种"绿"是**放水**。卡面最硬的要求恰好落在没人测的那一层。脚本级自查：

```bash
grep -rn "Module .* was never imported" <coverage.log>      # 直读硬信号
grep -rn "<ServiceImplClass>" tests/                        # 只在源码守卫字符串里命中 = 没测
```

## 2. 增量覆盖率必须逐条算，不能拿整文件比例冒充

口径（本项目已固化）：`变更覆盖率 = (变更 statement 清单 − (变更 statement 清单 ∩ coverage missing)) / 变更 statement 清单`，
`missing` 取自 `--cov-report=term-missing`，变更清单取自 diff 后的 statement 行号。要分**层**报：

- 新增完整模块（如 `app/services/<x>.py`）→ 变更清单就是整模块，**必须真实被导入**
- 既有大文件（如 `app/repositories/<y>.py` 700+ 行只新增 2 个方法）→ 只取新方法的 statement；
  未覆盖往往集中在**新方法的失败/回滚/冲突分支**（实测：`confirm_direction` 的冲突分支、
  `append_creative_turn` 的回滚路径、`bind_scoring_run` 三态 全是缺失区）
- 工人**如实报 `blocked` 而不拿整文件 47% 冒充增量结论**是正面样本 —— 派工单里要预先写明这条判据

## 3. 真因之下的真因：手搓持久化 JSON 夹具 = 无限返工

R04 连续两轮死在同一个地方：它为了让下游服务能读到"上游已有的持久化产物"，**手写了一段
`explanation_json`**，结果第一次缺 `relevance` 键、第二次缺 `scores` 键 —— 两次都**死在夹具回读**，
还没进生产行为断言。第三轮（R05）换了做法，一轮通过。

**规则**（写进派工单，别让工人自己摸索）：

> 夹具凡涉及**已由生产代码定义格式**的持久化载荷（JSON 列、快照、manifest 等），**一律走真实生产路径生成**：
> 用真实生成器（如 `PsychologyScorer`）→ 真实仓储 `save_*` 落库 → 生产回读函数取出 → 用它驱动被测对象。
> **禁止手搓**。若确实无法走生产路径，键结构必须从生产解包点逐字抄录（并断言回读能成功反序列化）。

好处不只是省一轮：夹具一旦人造，"持久化行为"其实是假测，下游契约根本没验证。

## 4. 工人索取白名单外读取时的正确处置（省一轮的关键动作）

工人停在"需要读 `app/repositories/<y>.py` 的某区间"（正确行为：白名单外先索取）。
调用方**不要**只说"批准了"就重派 —— 那等于让它继续摸索。三件套：

1. **自己只读查出它要的结构**（几分钟）：找到权威解包点（如 `_scoring_evidence`），把必需键清单抄进派工单，
   并注明"Hermes 抄录，与生产代码不一致时以生产代码为准"
2. **正式授权并留痕**：把文件名 + 行号区间 + 用途写进卡面「输入文件」的授权段（本项目卡面已有"已批准的白名单外只读授权"段）
3. **给正路**：把 §3 的"走真实生产路径生成夹具"直接写进授权说明 —— 多数情况下它根本不需要手搓

单次授权 ≤3 个文件；给行号区间而不是整个文件，省额度也防跑偏。

## 5. 撞额度/中断后的收尾分工

工人常在"跑剩余检查 + 写交付记录"这一步被杀。注意：**剩余检查（全量回归、整体覆盖率、迁移守卫）
本来就归调用方跑**，所以调用方可以立刻自己跑完，把"还剩什么"精确定位到只剩
**交付记录（`summary.json` + `结论.md`）**，再派一个**极小轮**收尾。

停工后先做：`git status` 核范围（确认半成品只落在白名单内）→ 自己复跑定向（通常已绿）→
跑联动/Ruff/全量 → 把**未跑项与已跑结果**写进诊断文档 → 下一轮派工单只指向该诊断文档。
**不要去 `resume` 抢救**：上下文已落文件，新会话更省（见 `resume-vs-fresh-session-and-delivery-record-gates.md`）。

## 6. 夹具来源（外部平台响应版）+ 开关型功能的真跑验收（2026-09-25 卡18 实测）

§3 管的是**我们自己定义的持久化载荷**；本节管**外部平台响应**——同一类错误的另一面，代价更大：

> 规则：凡声明「外部平台返回什么」的夹具（HTTP body / DASH 清单 / 媒体头 / 第三方 payload），
> **必须来自真实抓包或探针实测**，禁手搓「合理形状」。派工单要附上实测值（字段名 + 真实值），
> 并要求交付记录单列「真实形状覆盖」一节：每个实测值 → 用例名 → 断言。

卡18 实测：一个联网适配器携 **1007 passed** 全绿，合入后逐条真跑才炸出 **12 个阻断**，其中形状类全由
手搓夹具造成；最惨的是「无字幕后本地 ASR」这条**默认关闭**的路径——它一次都没真跑过，夹具的
四个假设**全是假的**：

| 夹具假设 | 真实响应 | 后果 |
|---|---|---|
| `dash.audio` 恰好 1 条 | **3 条**（不同码率） | 开 ASR 100% 失败 |
| 媒体 URL 是 443 | mcdn 镜像用 **`:8082`** | 被安全判据拒 |
| 下载头 `audio/mp4` | 头是 **`video/mp4`**（fMP4），条目才写 `mimeType=audio/mp4` | 媒体类型判据打脸 |
| 条目有 `length` 字段 | **无**（时长在 `dash.duration` 秒 / 顶层 `timelength` 毫秒） | 时长判据打脸 |

配套三条：

1. **开关型功能必须在卡内安排一次真跑验收**：`env 开关=true` + 真实样本 + 真库行级核对（本例验收口径是
   `transcript_source=ASR` 且 `transcript_segments>0`）。默认关闭 + 夹具自证 = **未验**，交付与验收都要显式标注。
2. **错误码归因要能暴露这类问题**：兜底把「任何非领域异常」收敛成一个业务码（本例
   `invalid_external_content`）会把排查引向错误方向（先怀疑素材失效，白查一轮）。兜底应报内部错误码，
   领域码只给真领域失败。
3. **卡面写死的安全常量若与真实响应冲突，先停下问用户再放宽**：本例「媒体 URL 只接受 HTTPS/443」与
   真实 `:8082` 冲突（不放宽则功能永远不可用）。正确做法：把实测值 + 放宽后剩余判据一并端给用户拍板，
   并在架构文档里留「谁在何时批准」的痕迹；放宽只针对必需的那一项（端口），其余 SSRF 判据一字不动。

探针配方（调用方自己跑，几分钟，省一整轮返工）：只打印**形状**——协议/主机/端口/字段是否存在/
`mimeType`/时长来源/正文前 4 字节魔数——**绝不打印签名 query 或原文**；先把真实值钉进派工单再派工。
