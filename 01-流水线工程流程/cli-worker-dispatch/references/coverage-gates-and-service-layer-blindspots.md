# 覆盖率作为验收信号：跨层盲区与增量口径（2026-09-18 实测，卡11）

工人自报「8 组 GWT 全绿」时，**覆盖率往往揭穿一个更深的缺口**：绿的是好测的那一层，硬要求所在的那一层根本没被导入。
本文给出判据、口径与处置流程。

## 1. 最强信号：`Module <pkg> was never imported`

原始 coverage 日志里出现下面这行（**不是** 0% 报告，而是一条 warning）：

```
CoverageWarning: Module app.services.creative was never imported. (module-not-imported)
```

⇒ **该模块在整轮测试中一次都没被 import**，等于它的全部语句 0 覆盖。实测卡11：`app/services/creative.py`（372 行）
承载**首轮建档、同 hash 回放、双检 CAS、配额预占/结算、失败 0 写** —— 恰恰是卡面最硬的契约 —— 而
`tests/` 全仓检索该类名只有 1 处命中，且是"源码守卫"里的字符串列表。工人的 8 组 GWT 全绿只证明了 agent 层与仓储层。

**两个连带陷阱**：
- 用 `--cov=<模块路径>` 指定一个未被导入的模块时，`term-missing` 报告里**可能根本没有这一行**，
  `TOTAL` 也不含它 → 只看 `TOTAL 47%` 会以为"覆盖了一半"，其实是"漏了一整个模块"。**必须 grep 日志里的 warning**。
- 覆盖率命令的退出码通常是 0（pytest 全绿），**不看 warning 就发现不了**。

## 2. 判据：绿层 ≠ 被证明
逐层问一句「本卡最难的那条要求在哪个文件里？」

| 要求形态 | 真正承载它的层 | 只在别处绿 = 没证明 |
|---|---|---|
| 事务原子性 / 回滚 | 仓储 + 服务编排 | 只测 agent 不算 |
| 配额预占 → SETTLED/RELEASED | 服务层（调 UsageMeter） | 只测仓储不算 |
| 幂等回放 / 双检 CAS | 服务层 | 只测纯函数不算 |
| 输入隔离（原文不得进 SYSTEM） | agent | 只测服务不算 |

## 3. 口径：**增量** statement coverage，禁整文件比例
门槛落在**既有大文件**上时（本卡只新增其中几个方法），整文件比例必然难看且无关：
实测 `app/repositories/<mod>.py` 整文件 24%–46%，但本卡新增方法 **94%（cases）/ 49.6%（scripts）**。

计算式（写进卡面与交付记录，工人自算、调用方复核）：

```
增量覆盖率 = (变更 statement 清单 − (变更 statement 清单 ∩ coverage missing)) / 变更 statement 清单
```

- "变更 statement 清单"由 `git diff -U0` 的 **+ 侧行号**映射到 coverage 的 statement 行号得出；
  定义行/导入延续行不冒充可执行 statement。
- 报告里要能逐文件列出：`变更 statement 区间`、`∩ missing 区间`、`分子/分母/百分比`。
- **禁 `--cov-branch`**；禁拿 `TOTAL` 冒充。

## 4. 处置流程（把补测派出去，而不是自己改测试）
1. 调用方**先自己复跑一次覆盖率**（同快照），确认 warning 与数字，别采信自报。
2. 把 **未覆盖的 statement 区间逐条抄进诊断文档**（哪一段、属哪个方法、对应哪条 GWT），
   连同覆盖目标（业务层 ≥80% / 基础层 ≥90%）一起交底。
3. 派工单要求：**只补测试，不改实现**；新建**服务层测试文件**必须先进白名单（卡面 §4 与 §3 命令同步）；
   用例**挂在既有 `test_gwt_11_*` 组名下**（行为组总数 ≤8 不破）；**禁假仓储冒充持久化**——
   服务层测试必须真 SQLite + 确定性 fake LLM + 注入固定时钟。
4. 测试若暴露实现缺陷 → 要求**停下如实报告**，不得自行改实现逻辑（否则实现与测试同源，验收失去独立性）。

## 5. 正面样本：工人自报 `blocked`
实测工人算完增量覆盖率后**没有拿整文件 47% 冒充**，明确写"未达门槛、状态 blocked、未运行项不得声称通过"。
这种 `blocked` 应当被当作**合格交付**（它把真问题暴露在验收阶段），处置是**带真因补测**，不是责难或加罚熔断。
反向教训也记一笔：若调用方只看"8 组全绿"就合入，服务层零覆盖会带着走 —— 这正是"沉没成本式放水"。
