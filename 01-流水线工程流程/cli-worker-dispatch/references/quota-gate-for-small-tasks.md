# 小任务的额度闸：resume 的代价、验证分工、字符 vs 字节（2026-09-17 实测）

> 归属：`cli-worker-dispatch` 的 SKILL.md「二、模型与额度」「四、验收」补遗。
> 为什么单独成文：本轮 patch 既有文件被读-写守卫拒绝（同 `dispatch-discipline-and-environment-triage.md` 的情形），
> 故以新参考文件落盘；后续维护请把要点并入 SKILL.md 对应小节。
> 触发场景：**用户额度告急**（本次剩 13%），用户原话「你要注意我额度只剩 13% 了」
> 「你还是用人工吧，但是叫它在烧完之前给你停止住」。

## 1. 实测：resume 是「按历史长度付费」，与任务多小无关

同一场会话里连续三次**有界小修**都走了 `codex exec resume <长会话>`：

| 派法 | 任务体量 | 实测 input | 结果 |
|---|---|---:|---|
| `resume` 长会话 | 改 1 行测试的篡改位置 + 30 次快速验证 | **832,993** | 完成，代价是任务本身的百倍量级 |
| `resume` 长会话 | 修一处并发冲突恢复逻辑 | **754,145** | 中途撞限 |
| `resume` 长会话 | 白名单挪一个文件 + 重跑 | **666,378** | 几乎一启动就撞限，**零产出** |

对照：同一用户的整场出卡/架构会议也不过 10–30 万 input 量级。结论：

1. **有界单点修复 → 新开会话，不要 resume。** resume 代价 ≈ 会话历史长度 × 轮数；
   「小修」塞进长会话 = 按历史付费。`resume` 只留给**必须共享上下文**的场合（架构续会、跨轮裁决）。
2. 会话被恢复了模型也要留意：`resume` 时 CLI 会提示
   `This session was recorded with model X but is resuming with Y` —— 这本身不是错误，但如果产出质量异常，
   优先怀疑「续会上下文 + 换模型」，改用**新会话**重派而不是继续加热会话。

## 2. 验证分工：多轮循环必须留在调用方（本次最大的黑洞）

派题里写「连跑 20 轮 + 加压 5 轮」「auth 套件 10 轮」这类要求，是本会话最贵的一笔 —— 每轮都把上下文重放一次。

| 谁跑 | 跑什么 | 成本 |
|---|---|---|
| 工人 | **最快的单次/短循环**定向（例：单个 0.4 秒的测试文件 ×30 次 ≈ 15 秒；或一次并集套件） | 低 |
| 调用方（Hermes） | 稳定性多轮复跑、逐模块覆盖率、全量回归、PERF 复跑 | **零额度**（本次调用方自己连跑 12 轮 + 14 轮 + 8 轮，0 失败） |

规则：**「要 N 轮证据」= 调用方自己跑 N 轮**；派题里只写「跑一次定向并给原始输出」。
工具的 `terminal(background=true)` 循环是免费的，工人的循环是要钱的。

## 3. 额度告急时的带闸模板（六条，直接抄进派题）

```text
额度告急任务（用户额度仅剩约 <X>%）。本任务只做一件小事，必须极省额度。
1) 只允许读 <N> 个列明文件（<逐条列出>）；禁探索式全仓 grep、禁整读设计文档。
2) 不运行任何测试（文档/契约类任务）；或只跑 <唯一一条最快的定向命令>。
3) 工具调用总数 ≤ <N> 次；做不到先报告再继续。
4) 任何命令出现用量上限提示 → 立即停止并如实报告已完成部分。
5) 同一失败两次不成就停：不许重试第三次、不许自行扩大范围。
6) 产出限长（如新建小结 ≤60 行 / ≤2,000 字符），白名单只有 <文件列表>。
禁止：写入/删除/移动白名单外任何文件；git；装依赖；清理临时目录。
```

配套判读：**熔断 > 完成度**。额度告急时宁可要「改完了 + 验证由我跑」，不要「它跑完整套证据」。
实测这条带闸派题把「改一行测试」压到 10 次工具调用内（同时因为用了 resume，仍未省下历史重放的成本——
所以第 1 条同样是硬要求）。

## 4. 字符 ≠ 字节：体量预算的计数口径

卡面纪律「执行卡 ≤8,000 / 测试卡 ≤6,000 / 合计 ≤14,000」指的是**字符数**，但 `wc -c`、`ls -l` 给的是**字节数**；
中文 UTF-8 约 1.8–2.7 字节/字符 → 用字节判会得出「超限 2.7 倍」的**假警报**（本次差点误判返工）。

```python
t = pathlib.Path(card).read_text(encoding='utf-8')
print(len(t))        # 字符数：唯一正确口径
print(t.count('\n') + 1)   # 行数
```

工人自报 4,621 字符、调用方测到 8,263 字节 → **两者都对**，是口径不同。任何「文档体量/结论限长」的硬约束，
派题与验收都要写明是字符还是字节。

## 5. 派工指令落成文件（省额度 + 可重放）

把「bash 命令 + 提示词全文」落成 `project/outputs/<NN>/卡<NN>_派工指令.md`：

- 换会话、换人、定时补跑都能**一字不差重放**，不依赖 session id（也不会踩「凭记忆写 id」的坑）；
- 需要 resume 时，用户或 cron 只需读这个文件即可派工，不必再让模型重述一遍长提示词（重述本身也在烧上下文）；
- 中断交接、额度恢复后补派、以及「同一派题换模型重发」都靠它。
