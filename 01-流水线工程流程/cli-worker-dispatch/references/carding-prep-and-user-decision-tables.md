# 派题前的准备 + 「待用户拍板决策摘要表」（2026-09-19 卡12c/12e 实测）

补充（不替代）`templates/card-authoring-brief.md`（出卡派题的八段骨架）与
`initial-review-numeric-and-scope-verification.md`（初审怎么核数字）。
本文收录三件在卡12c/12e 上被验证有效、但骨架里没写的事。

## 1. 事实基线：**先用代码查实，再写进派题**

派题里写"应该有/可能没有" = 让架构师猜 = 猜错就返工一轮。凡涉及"现状有没有做某功能"的需求，先跑取证命令：

```bash
grep -n "password" app/api/schemas.py                                  # 裸 str 还是带 min/max_length？
grep -rniE "rate_limit|throttl|lockout|too_many" app/ --include=*.py   # 0 命中 = 完全没做
grep -rn "middleware" app/ --include=*.py                              # 有无限长/限流中间件？
grep -n "status\|role" app/db/models.py                                # 零迁移是否可行（列已存在？）
grep -rln "create_admin\|seed_admin" scripts/ tools/ 2>/dev/null        # 有无引导入口（本例：无）
```

把「缺口 + 证据（`文件:行` 或 grep 输出）」逐条写进派题的"事实基线"段，并**点名一条容易混淆的项**
（本例：卡12c 给脚本加的"密码 12～1024"护栏只在脚本入口，**不覆盖 HTTP 注册/登录**，必须写清楚，
否则架构师会以为密码策略已做）。

## 2. 涉及取值/阈值/新增错误码/存储选型的卡 ⇒ 要求架构师产出「待用户拍板决策摘要表」

在派题里明确要求：裁决文档中**单独一节**给出表格，列固定为
`决策点 | 推荐 | 备选 | 影响面 | 是否可后补`，并写死一句
「**未批准不得擅自用近似项顶替**（如不得用 `quota_exceeded` 代替限速码）」。

实测输出（卡12e，8 行）：密码策略数值 / 密码 HTTP 码 / 限速维度与阈值 / 限速 HTTP 码 /
请求体限长与超限码 / 注册枚举取舍 / 是否允许迁移。每行都带备选与"可后补"判断。

**调用方的用法**：收到后**只把这张表转给用户拍板**（外加自己初审的补充意见），
不要求用户读整篇裁决 —— 用户的决策成本被压到一张表。

## 3. 执行顺序前提：两张卡改**同一批文件**时，必须串行

例：12c（管理员管理）与 12e（认证加固）都会改 `app/services/auth.py` + `app/api/*`。
处置三件：
1. 后卡卡面写「**执行前提＝前卡已合入**」；若开工时前卡未合入 → **停下报告**，不得自建前卡的产物；
2. 后卡的联动精确期望值按「**当前 + 前卡新增**」推算，并要求工人**开工前先读前卡交付记录核对真实总数**，
   不一致以实测为准并在交付记录里说明差异；
3. 把"另一张卡的改动**不在本卡范围**"逐条写进硬边界（本例："不要顺手改密码策略/限速/请求体限长"），
   防工人跨界。

## 4. 卡面字符上限的压缩技巧（双卡 ≤8000/≤6000/合计 ≤14000）

- **细节上移**：字段清单、DTO 全字段列表放**任务卡**；测试卡只留"DTO 名称 + 见任务卡 §2"。
  实测靠这一手把测试卡从 6,239 压到 6,000。
- **白名单按路径组列**（≤6 组）而非逐文件列举。
- **我方的修正文字要短**：把"为什么"留在任务卡/裁决，测试卡只留结论 + 精确值。
- 改长中文文档时**按行号改写**（先 `read_file` 拿到行号，再用脚本按 index 替换），
  比正则锚点稳 —— 中文全角标点/换行会让 `replace` 静默不命中（实测 `AssertionError: 锚点未命中`）。
- 编辑脚本一律**落文件再执行**：内联超长 heredoc 会被 `BLOCKED (hardline): command parser limit` 拦，
  且 `python -c "…"` 里的反引号会被 shell 当命令替换吃掉（实测把 git hash 吃没了）。
  正确姿势：`write_file` 落 `.tmp-hermes/patch_x.py` → `python -B 该脚本` → `rm -rf .tmp-hermes`。
- 每次改完立刻量字符：`len(open(path, encoding='utf-8').read())`，并断言 `≤` 上限（别靠估算）。
