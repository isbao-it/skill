# 额度记账更正与「探活成本」实测（2026-09-18）

对 `references/quota-probe-and-caller-economy.md` 第一节的**数字更正与补充**（该文件里
「探活 1–2k token」的估计偏低，实际高一个数量级）。

## 一、探活的真实成本：2 万 token 级，不是 1–2k

同一条 `codex exec -m <模型> -C <项目根> "只回复两个字：正常"`，因为会把**项目规则文件 +
仓库上下文 + 工具定义**一起注入，实测烧 **23,349 token**。

同项目对照：出卡任务（`model_reasoning_effort="high"`，产出裁决+双卡）整场 **136,033 token**。

结论不变（探活仍划算：对照「白烧 82,395 token、零产出」），但要改的是**预期**：

- 探活 = 一次**完整上下文注入**，不是"几乎免费"
- 不要在一次会话里反复探活；一次派工链只探一次
- 额度只剩个位数百分比时，探活本身也可能把余额吃穿 → 此时该做的是**等恢复**或换工人

## 二、记账法（「resume 续跑 vs 新会话」这类对比别靠印象）

| 记录项 | 取法 |
|---|---|
| `tokens used` | `grep -a -A1 "tokens used" <运行.log>`（每个 run 末尾一次，数字在下一行） |
| `session id:` | 派工会话**一跑起来就抄进 `project/outputs/<NN>/session_id.txt` 落盘** —— 主代理会话可能被压缩/重启，id 丢了就再也 `resume` 不上 |
| 对照基准 | 最近一次**新会话执行**同类卡的 tokens / 轮数 / 是否返工 |

固定留一份 `project/outputs/<NN>/额度实验_*.md`：假设 → 本次数字 → 对照基准 → 结论（未跑完就写"待取"）。

## 三、纪律（别把假设写成结论）

- **小活禁 resume**：历史实测 `codex exec resume` 重放烧 **832,993 token**；小修一律新开会话 + 紧派题
- `codex exec resume <id>` **只认 `-c`**，换模型写 `-c model="<名>"`（不认 `-m` / `-s`）
- 「出卡会话直接 resume 续执行」在本项目当时**仍是待实测项**（用户指定要做 A/B）：没拿到对照数字前，
  任何文档/技能里都**不许**把它写成推荐做法或省额度结论
- 用户会主动关心「这样会不会省额度」→ 如实回报：省的是"摸索轮数"，**不省"每轮重放"**
  （会话越长每轮重放越贵），所以判断依据必须是**实测 tokens + 轮数**，不是感觉
