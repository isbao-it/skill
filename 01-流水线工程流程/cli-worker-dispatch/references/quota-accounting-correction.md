# 用量取数口径修正（2026-09-15 实测；优先于 quota-budget 那份的第一节）

> **⚠️ 先读这条**：本 skill 的 `scripts/codex_quota_audit.py` 在 2026-09-15 之前是**取最后累计值**
> 的算法（`rec["input"] = cur`，并用 `max(cur - prev, 0)` 算每轮重放量）。实测证明这会
> **低估 10.4%**（单会话最多低估 4.2 倍），因为累计序列并不总是单调。修复方案见本文第三节。
> 在被修正之前，**不要用它的 input 合计下"省了多少"的结论**；改用本文口径复算。
> 该文件与 `references/quota-budget-and-independent-review.md` 第一节讲同一件事，冲突时以本文为准。

## 一、三条硬口径

| 指标 | 规则 |
|---|---|
| 调用数 | `token_count` 事件数（= 一次真正产生 usage 的模型调用）。用户消息数、工具调用数**另计**，混入会把成本算高 |
| input / cached / output | **分段求和**：累计序列呈现回落（上下文压缩 / 重置）即判为新段，段内取最大值后相加；单段会话即取最后值 |
| 缺失 | 一律 `null`（显示层不填 0 冒充测量）；探针会话与 `auto_review` 会话**单独归类**，不计入任务成本 |

## 二、两个错误口径的实测代价（都会产出"可信外观"的错误结论）

| 错误做法 | 后果 |
|---|---|
| 把每次 `total_token_usage` 相加 | **虚高 22 倍**（累计值当增量用：11.0 亿 vs 真实 4,991 万） |
| 只取最后一个累计值 | **低估 10.4%**（4,991 万 → 5,512 万）；**非单调单例最大低估 4.2 倍**（887,423 → 3,760,876） |
| 用 `max(cur - prev, 0)` 算每轮重放量 | 把回落**悄悄抹成 0**，等于既丢数据又不报警 |

实测非单调来源：3 个早期会话在回落点后**从零重新累计**（上下文压缩/重置）。因此段数必须显式上报，
不能只给一个总数。

## 三、drop-in 实现（把这段替换进 `scripts/codex_quota_audit.py`）

```python
def seg_sum(seq: list[int]) -> tuple[int, int, int]:
    """分段求和：序列回落即新段，每段取最大值后相加。

    参数：seq —— 累计值序列（各轮事件的 total_token_usage.input_tokens）
    返回：(修正后总量, 段数, 回落次数)。空序列返回 (0, 0, 0)。

    为什么不能只取最后一个值：实测存在"回落点后从零重新累计"的会话
    （上下文压缩/重置），只取最后值会漏掉前面整段，最多低估 4.2 倍。
    """
    if not seq:
        return 0, 0, 0
    segs, cur, resets = [], [seq[0]], 0
    for i in range(1, len(seq)):
        if seq[i] < seq[i - 1]:
            segs.append(max(cur))
            cur = [seq[i]]
            resets += 1
        else:
            cur.append(seq[i])
    segs.append(max(cur))
    return sum(segs), len(segs), resets
```

接入要点：

1. 先用**原始序列**（`ins: list[int]`）逐轮 append，**不要在读取时做任何 max(…,0) 加工**
2. 会话总量 = `seg_sum(ins)[0]`（cached / output 同样处理）
3. 每轮重放量 = 相邻差，**允许负值**（负值就是回落信号）；统计均值时只取正值，但把 `resets` 一并输出
4. 汇总保留 `segments` / `resets` 两个字段，便于发现"这个账号的会话经常被压缩"
5. 分类：`probe`（单次调用 + 短问句，如"只回一句话/两个字"）与 `auto_review` 不计入任务成本

## 四、确定性要求（工具改动的验收方式）

1. 连跑 3 次 `--json`，输出文件 `sha256` **完全一致** → JSON 里**不得**包含运行时间戳或随机序
2. 抽检 4 个会话与手工独立核算比对，**必须包含 1 个非单调会话**（否则测不到分段逻辑）
3. 内置 `--self-test` 断言至少覆盖：单调序列、一次回落、两次回落、回落计数、空序列

```python
check("一次回落分段相加", seg_sum([10, 20, 5, 15])[:2], (35, 2))      # max(10,20)+max(5,15)
check("两次回落分段相加", seg_sum([100, 10, 40, 5, 7])[:2], (147, 3))  # 100+40+7
```

## 五、结论纪律

- **不得**用 token 数或缓存比例换算订阅额度节省（缓存折扣 / 订阅额度 / API 费用是三种口径；
  缓存命中 91% ≠ 省 91% 额度）。本地读不到额度就记 `null`，不做推测。
- 对比前后数据先看**客观项**（产物体积/产出格式是否达标），再看轮数/input，并注明样本量与任务规模差异——
  实测出现过「26 轮 vs 98 轮」但两者任务体量不同，**不能据此宣称省了 82%**；需同类任务 ≥3 张。
