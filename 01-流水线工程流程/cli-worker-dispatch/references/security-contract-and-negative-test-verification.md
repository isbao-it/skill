# 外部输入的卡：安全契约、负向测试与「达标但没证明」的判读

来源：2026-09-17 卡07a/07b 实测（B站采集适配 + ASR）。触发条件：**任务涉及采集/解析第三方数据**
（爬虫、平台 API、上传文件、语音/图像、任何"外部文本会进 LLM"的路径）。

## 一、用户明确要求（2026-09-17 原话）

> 「要记得做一些安全防护，防止爬取恶意数据啊，或者是输入恶意数据」

这不是"注意安全"一句话，而是**必须落成可测契约**。做不到"可测"就不算防护。出卡/派工单里
没写以下 7 类，视为卡不合格：

1. **SSRF / 白名单**：允许的 host 集合**逐字列出**（不接受通配符）；仅 https；端口白名单；
   重定向跳数上限 + **逐跳重验**（scheme/host/port/DNS/实际连接 IP）；私网、回环、链路本地、
   保留、未指定、**多播**、IPv4-mapped 非公网、IP 字面量**全部拒绝**；DNS 解析出的**每个**地址
   都要校验（一个非公网即整体拒绝）+ 连接后复核 peer IP（防 DNS rebinding）
2. **拒绝服务**：响应体上限（**解压后**）+ **解压比上限**（防压缩炸弹）；连接/读超时分设；
   每域并发；RPM；每日任务数与分页/条数上限；ASR 类音频的字节与时长上限；
   **ReDoS 禁令**：禁嵌套量词与灾难回溯，正文按线性遍历，任何新增正则须有最大输入长度
3. **内容卫生**：Unicode NFKC + 换行统一（CRLF/CR→LF）+ 剥离 `Cc`/全部 `Cf`
   （**含零宽字符 U+200B、双向控制符 U+202A..U+202E**）+ 超长按 code point 截断或拒绝（逐字定其一）
4. **提示注入隔离**：抓回的标题/标签/评论/字幕/ASR 文本一律标 `UNTRUSTED_EXTERNAL`，
   **永不拼进 system/developer prompt**，只作结构化 user/tool 数据消费（为下游 LLM 卡预留契约）
5. **fixture / 测试数据安全**：只能从白名单目录加载；禁路径穿越（`..`/绝对/盘符/UNC/NUL/符号链接）；
   递归敏感扫描（凭证、UID、个人信息、IP、真实路径）；强制脱敏；合成数据不含真人语音/信息
6. **存储与回显**：一律参数化 SQL（禁拼接）；错误码稳定且**不回显原始输入** ——
   测试里直接写 `assert raw not in str(caught.value)`
7. **安全常量表**：域白名单/大小/长度/时长/超时/并发/RPM/跳数/截断阈值**集中成一张表**逐字进卡，
   并写明「配置只能收紧不能放宽」

## 二、覆盖率达标 ≠ 防护有效：拒绝分支的判读

卡07a 第一次交回：覆盖率 **81.17% ≥ 门槛 80%**，形式上达标。但把未覆盖行**按函数归类**后：

```
_is_public_address   2/8 未覆盖   ← 私网/回环/多播判定
_validate_addresses  2/6 未覆盖   ← 「多地址中一个非法即整体拒绝」
_scan_sensitive      3/18 未覆盖  ← fixture 敏感数据扫描
_validate_fixture_path 4/26       ← 路径穿越
sanitize_external_text 5/25       ← 控制符剥离
validate_response_limits 1/9      ← 解压比
_parse_utc           4/11         ← 坏时间戳
```

未覆盖行**集中在安全/校验函数的拒绝分支** = 防护逻辑完全没有测试证明。
**判读规则**：达标也要补负向用例（目标 ≥90%）；若未覆盖行只是零散的正常路径边缘，可放行。

## 三、负向测试真的会抓到漏洞（实例，务必照做）

补负向用例时抓到真实 SSRF 漏洞：

- Python 3.11 的 `ipaddress.is_global` 对**多播地址**（如 `224.0.0.1`）返回 `True`
- 原白名单实现因此会**放行多播地址**
- 修法：`address.is_global and not address.is_multicast and (mapped is None or mapped.is_global)`

只有「拒绝用例」能走到这些分支 —— 正常路径永远走不到。**这就是要求补负向用例的正当性**，
不是洁癖：一次投入换来一个真实漏洞的修复。

## 四、补负向用例的派工单怎么写

- **逐函数列靶子**（不要写「提高覆盖率」）：给每个未覆盖的安全函数写出**必须断言的具体场景**，
  如「私网 10./172.16-31./192.168.、回环 127.、链路本地 169.254.、多播 224.、IPv4-mapped 非公网」
  「多地址中一个非法 → 整体拒绝」「解压比超 20:1 → `response_too_large`」
- **只增不改**：禁止删除/跳过/放宽任何既有断言；禁止把安全测试降级为"建议"
- **fixture 变体用 `tmp_path` 现场构造**，不新增 fixture 文件（否则撑爆白名单）
- **允许最小修复**：写「若某条负向用例揭示实现缺陷，允许最小修复使代码符合已冻结契约
  （不得改契约本身），并在结论里逐条列『用例 → 暴露的缺陷 → 修法』；若发现契约本身矛盾则停下报告」
- **禁止凑数**：明确写「不许空断言、不许为达标写假用例」

## 五、返工轮的收尾同样要验收

负向补测的返工常常**卡在格式问题上按纪律自停**（本例：2 处 E501 行长超限，同失败两次即停），
此时交付文档（结论/summary/证据日志）**往往还没更新**。判读：这不是失败，是熔断生效。
处置 = 派一个**纯收尾单**（≤12 次调用）：只修行宽/格式化 + 真跑并落盘证据日志 + 更新结论与 summary
到校验 0/0，并明文写「不改任何断言语义、不改实现逻辑」。

同时提醒工人：**日志一律在 git-bash 用 `> file 2>&1` 重定向** —— PowerShell 重定向产出
UTF-16 带 NUL 的乱码文件，看起来像"日志损坏"。
