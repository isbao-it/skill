# 派工纪律补遗 + 环境类阻塞的分诊（2026-09-16 实战）

> 归属：`cli-worker-dispatch` 的 SKILL.md「一、派工指令骨架」「三、失败模式」「四、验收」的补遗。
> 为什么单独成文：本轮无法改写既有文件（读-写守卫），故以新参考文件落盘；下次维护时请把要点并入 SKILL.md 对应小节。

## 1. 派题约束要写「写入 + 删除 + 移动」，并预留机械连带授权

派题结尾固定一句：**除任务列出的文件外不得写入、删除或移动任何文件**，逐一点名禁止「顺手」更新实时解释/学习笔记/模块文档/架构/裁决/README，**以及"顺手清理临时目录/废弃文件"**。

- 只写"禁止写入"不够：实测工人仍会删掉它认为多余的 3 份未入库交付文档（后来从 rollout JSONL 反解恢复）。
- **同时**：白名单过窄会让纪律工人停在门口等授权（同日 3 次，白烧一轮）。新增模块/端口/迁移/Settings 键时必撞**冻结清单型契约测试**（「`app/repositories/*.py` 文件集合 == 7 项」「实现类→公开方法集 == 27」「端口协议集合」「期望 JSON 清单」）。派题时提前写：**「允许扩展该测试的期望集合（只许加，不许删/放宽/skip/xfail），改完在回报里说明」**。
- 两类禁令并存：可以扩期望集合，**不得**用删断言、`omit`、扩大测试范围的方式让数字好看。

## 2. 工人报「环境类阻塞」时：先复现，再处置

症状例：`PermissionError: [WinError 5] 拒绝访问: <项目>\.pytest_tmp\card04b-directed`（连带 15 errors，零绿灯）。

1. **先用同一条命令在调用方自己的 shell 里复现**。本轮实测：同目录 Hermes 侧可正常创建子目录 → 属工人沙箱进程的特例，不是仓库损坏，**不要**先去改权限或删目录。
2. 处置模板：①如实记录原报错；②**授权改用独立可写临时根**（system temp）完成验收；③要求结论里**同时**贴「原命令报错」与「替代根绿灯」两组原始输出；④声明未改 ACL、未删目录、未绕过验收。
3. 别把特例写成"该目录不可用"的长期结论——环境会变，写死了以后会被当成借口。

## 3. `resume` 的 session id 禁止凭记忆写

凭记忆写的 id 会空跑一轮：`Error: thread/resume: thread/resume failed: no rollout found for thread id <id> (code -32600)`（exit 1、零产出）。

```bash
# 用派题里的一句独有短语反查（中文在 rollout 里是 \uXXXX 转义，用 ASCII 片段最稳）
cd ~/.codex/sessions/2026/09/16 && for f in *.jsonl; do
  grep -q '执行【04b 计量与策略批】' "$f" && echo "$(basename "$f")"
done
# rollout-2026-09-16T23-48-09-<uuid>.jsonl → 文件名尾部 uuid 即 session id
```

**更稳的做法**：把整条派工指令（bash 命令 + 提示词全文）落成 `project/outputs/<NN>/卡<NN>_派工指令.md`，换会话/换人/定时作业都能一字不差重放，不依赖任何 session id。定时补跑（额度恢复后自动开工）也照这个文件派。

## 4. 分批任务的覆盖率口径：别把虚低当失败

包级 `--cov=<包> --cov-fail-under=80` 在只跑**本批**测试时必然虚低（实测 72.75%，未运行的旧模块进了分母）。

- 判据：**本批改动模块逐模块**达标（基础层 ≥90%、服务/业务层 ≥80%）即通过；
- 包级与"整体不稀释"留到**父卡最终统一重跑**（全测试目录一起跑）判定；
- 命令写逐模块形式（`--cov=app.domain --cov=app.repositories.identity …`）；禁止 `omit`/`no-cover` 规避，禁止为抬数字扩大测试范围。

## 5. 模型口径是易变的

模型由用户在会话中反复改判（2026-09-12 ~ 09-16 共 4 次：astra 写代码 → sol 写代码 + astra 出卡 → 全 sol → 全 astra → 本轮又两次点名 sol）。

- **每次派工前重读用户最新一句**；不要按"角色"自行分模型（已被纠正多次）；
- **每份派工回报里写明本次所用模型**，让用户一眼能纠正；
- 模型可用性表（哪些名字存在、哪个要求 CLI ≥0.154.0）见 `references/codex-cli-ops-notes.md` §1；"默认用哪个"以用户最新指令为准。
