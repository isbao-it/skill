# 新增仓储/端口模块时，派工单必须自带的合同条款（2026-09-17 实测）

配套 `SKILL.md` §一（派工指令骨架）、§四（验收）；本文是对
`references/codex-exec-dispatch-pitfalls.md` §3「连带坑」的执行级补充。

## 1. 冻结契约测试：工人**永远不会自己发现**它红了

项目常有「冻结清单」型契约测试（例：`tests/unit/repositories/test_repository_contracts.py`），
它硬编码三样东西：

- 目标目录下的**文件名集合**（`app/repositories/*.py`）
- **实现类 → 端口** 映射
- **公开方法总数**

因此**每新增一个仓储文件或端口，这个测试必失败** —— 本机已连续踩三次（04a → 05 → 06）。

**为什么必须在派工单里事前预授权**：工人按纪律**只跑定向用例、不跑全量回归**（全量归调用方），
所以它**看不到这个失败**，还会在交付结论里诚实地写
「未触发白名单扩展；未修改任何既有测试文件」—— 字面上毫无问题，但全量回归必红。
不预授权的代价：白烧一整轮（06 那轮返工正好撞上账号额度上限，直接报废重排）。

**派工单照抄这三句**：

1. 白名单**追加该测试文件**，并**预授权最小扩展**：只增条目/计数，**不放宽、不删除、不跳过任何既有断言**；
2. 明确写「**该失败是本卡的预期产物，不是要回退实现**」；
3. 给出**精确期望值**：新实现类名、端口名与**逐方法名**、更新后的方法总数——
   这活机械到不该让工人推导（实测：把它写成「6 个方法、总数 42→48」后，一次通过）。

**验收侧同样固定一条**：跑全量回归时先判失败类型——若就是这一类，直接按上述口径补测，
**不要打回实现**（打回等于让工人改一个它看不到的东西）。

## 2. 多个小活：串行跑在**一条**后台命令里

同一 Codex 账号**同时只跑 1 个主动任务**（并发既抢额度、也可能直接撞限额）。
「收尾小修 + 下一张卡出卡」这类两件套，不要开两个后台会话，串成一条提交：

```bash
codex exec ... -o <日志A> "$(< 提示词A)" > <运行日志A> 2>&1; echo "A_EXIT=$?" >> <运行日志A>; \
codex exec ... -o <日志B> "$(< 提示词B)" > <运行日志B> 2>&1; echo "B_EXIT=$?" >> <运行日志B>
```

一次 `terminal(background=true, notify_on_complete=true)`，完成通知只来一次。
**每个 job 必须单独 `echo "…_EXIT=$?"`**，否则前一个的失败会被后一个的退出码盖掉
（看到 `EXIT=0` 就以为两件都成了）。

## 3. 交付物有机器校验器 → 把命令写进派工单

若项目为交付物提供了校验器（例：`summary.json` 的 `project/templates/validate_summary.py`），
派工单里要**写全命令**并要求 **0 ERROR / 0 WARN**，而不是含糊地写「按既定模式交交付物」。
调用方验收时**自己再跑一遍**：校验器只保证结构与字段事实，不保证内容正确。

## 4. 读取白名单要覆盖「实现该类模块**必然**要读的基础文件」（2026-09-18 实测，连栽两次）

工人守纪律时会**停在白名单外索取**——它会明确列出文件名 + 原因 + 拟读章节，**一个文件都不写**。
这是正确行为，但代价是一整轮（实测 98k、188k token 各一次）。两次都栽在**出卡/初审时把读取面写窄了**：

| 卡在做什么 | 卡面必须预先列入只读白名单的文件 |
|---|---|
| 实现新仓储 / 新增端口实现 | `app/db/models.py`（真实列名与关联）、`app/db/session.py`（引擎/Session 工厂/事务钩子）、`app/domain/entities.py`（命令 DTO/枚举/值域） |
| 写组合根 / 装配应用（如 `app/main.py`） | 上述三件 **+ 既有 `app/repositories/*.py`、`app/adapters/*.py` 的类与 `__init__` 签名**（否则它无法正确装配） |
| 补服务层/集成测试 | `tests/conftest.py`（既有夹具）与同类测试文件（当样板） |

**写法**：一条「**初审补齐的只读授权**」写进卡面 §输入白名单，并附约束
「**先 grep `^class `/`def __init__` 定位再局部读，禁整份通读**」——既给足权限，又控住 token。
再配一句「**写入**仍严格限于写入白名单」，避免把只读授权误读成写入扩张。

**判断口径**：只要卡面要求新建仓储实现、组合根装配、或新增端口实现，**默认就该把这四类文件列进去**；
等工人来索取 = 已经白烧一轮。反之，纯算法/纯文案卡不必扩，别把读取面写宽导致上下文膨胀。

## 5. 收尾小活也要带范围锁

「就改 4 行」的收尾派工同样要写全：白名单（含被授权扩展的那**一个**测试文件）、
禁范围外一切写入/删除/移动、禁 git、只跑定向、输出重定向到日志。
实测这类小活正常只花几千 token——把它写成小合同，成本不变，风险归零。
