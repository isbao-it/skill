# 额度/中断后的一轮收尾（续跑单模板）（2026-09-19 实测，卡12e）

配套 `SKILL.md` §三「失败模式：先看磁盘，再决定重跑」。本文件只补两件在 `worker-interruption-and-recovery.md` 里还没写的东西：
**撞额度后调用方零成本核验**、**续跑单的逐字模板**。

## 1. 撞额度后别干等：调用方自己零成本核验（不花 worker 额度）

实测：卡12e 在 ~85% 处被 `ERROR: You've hit your usage limit … try again at 11:31 PM` 掐断。
但 worker 的**实现与测试是实时落盘的**——当时磁盘上已有 `app/api/middleware.py`(87 行新文件)、
`app/services/auth.py`、`app/main.py`、`app/api/{errors,routes,schemas}.py`、`scripts/create_admin.py`，
以及 3 个新测试文件（合计 636 行），`R01/details/` 里还有它留下的 `pytest-api.log=9 passed`、
`pytest-focused.log=16 passed`、`ruff-attempt1.log=2 fixable`，**只缺 `summary.json` 与 `结论.md`**。

**调用方动作（全部在本地，零 worker 额度）**：

1. `git status --short` → 列出真实落盘面，核对是否都在卡面白名单内（越界要单独报告）
2. 读它留下的 `details/*.log` 尾部 → 拿到它自报的中间结果（只能当线索）
3. **自己跑一遍定向用例**：`pytest tests/<相关目录> -q`（本地解释器，几秒到几分钟）
   - 全绿 ⇒ 只差交付记录，进入第 2 节模板
   - 有红 ⇒ 续跑单里写出精确缺口
4. 实测结论：那一轮结果是 **287 passed + Ruff `All checks passed`**——即"代码其实已经写完且干净"，
   只是收尾被打断。**若直接重跑整场，等于再烧一小时额度。**

## 2. 续跑单模板（照抄，实测一轮收尾成功）

```
按卡收尾卡NN（R02：续跑 R01 被额度中断的收尾）。**全新会话。R01 的实现与测试已全部落盘在工作区，
不要重写、不要回退、不要重跑红灯。**

## 背景（R01 中断点，已由 Hermes 只读核实）
<列出真实落盘文件 + 已有日志的数值 + 明确缺什么>

## 本轮任务（只做收尾，不改已完成的设计）
1. 先读卡面/裁决与你自己 R01 写下的实现与测试，**核对卡面每一组 GWT 是否都已覆盖**
   （未覆盖的补齐测试；**不得放宽任何断言**）
2. 清 lint 到退出码 0（R01 可能残留可自动修复项）
3. 复跑并留证：定向 / 覆盖率（按卡面口径）/ §5 联动 / lint，basetemp 用「已存在父目录下的新子目录」
4. **补齐交付记录**（沿用 R01 目录，**不要新建 run_id**）：
   - `summary.json` 逐字遵守 schema 并自跑校验器到 **0 ERROR / 0 WARN**
   - **`结论.md` ≥10 行实质摘要**：判定 + 实现了什么（逐项对卡面组）+ 每条命令与结果对照 + 未验证项
     （禁止只写一行 `ready_for_review`）

## 硬边界 / 熔断（原样保留）
<六组白名单 + 基础只读；零迁移零新依赖；不改无关契约门；禁 git；同因失败 2 次即停>
首行回报 CARDNN_R02_OK / CARDNN_R02_FAIL:<原因>
```

**两个可调项（省额度）**：
- 收尾轮**降一档 effort**：执行轮 `-c model_reasoning_effort="high"` → 收尾轮 `"medium"`（实测够用）
- 想完全自动：挂**一次性** cron 到额度恢复时刻之后（如恢复 23:31 → 挂 23:35），
  并让 cron 第一步先跑一次**最小额度探针**，探针失败就只报告、不派工

## 3. 写这类续跑单前必须做的一件事

把**落盘事实写进续跑单**（文件名、行数、已知日志数值、缺什么）。
不写事实、只写「继续上次的活」，worker 会用一轮去重新探索它自己昨天的产出——
实测这类"复述现状"开销可达 8–18 万 token。
