# 🏗️ 软件开发自动化流水线

## 角色分工

- **🧑 你（决策者）** — 审核架构、审批选型、确认模块、决定是否合入
- **🤵 Hermes（架构师+PM）** — 需求分析、技术选型、架构设计、模块拆分、调度Claude、代码审查、Bug分析
- **⚡ Claude Code（程序员）** — 写代码、跑测试、修复Bug

## 六阶段流程

### 阶段 0：需求录入
用户说需求 → Hermes 反问澄清模糊点

### 阶段 1：需求分析 + 架构设计
Hermes 产出《需求分析与架构方案.md》，包含：
- 功能拆解（核心/扩展）
- 技术选型（至少2个方案，含优缺点）
- 整体架构（模块划分、数据流、接口）
- 模块清单（职责、边界、依赖）
- 模块拆分建议（依赖顺序）

### 阶段 2：你审核架构方案
🟢 通过 → 阶段3
🔴 驳回 → Hermes 修改后重新提交

### 阶段 3：模块细化 → 拆为小任务
Hermes 按模块拆成任务卡片 → `_Tasks/待执行/`
每个卡片含：目标、具体要求、输入文件、输出规范、测试要求

### 阶段 4：Hermes 调度 → Claude 执行 → 分层测试
按模块依赖顺序推进，可并行。

**三层测试策略（越新/越基础 → 测试越严）：**

```
基础层模块（如数据库、核心引擎）
    → 任务测试：单元测试覆盖率 ≥ 90%
    → 模块测试：集成测试 + 边界测试 + 异常测试
    → 强度：最高

业务层模块（如API、业务逻辑）
    → 任务测试：单元测试覆盖率 ≥ 80%
    → 模块测试：集成测试 + 主要边界测试
    → 强度：中等

展现层/工具层（如CLI、简单工具）
    → 任务测试：单元测试覆盖率 ≥ 60%
    → 模块测试：冒烟测试
    → 强度：正常
```

**每个任务闭环：** Claude 读卡 → 写代码 → 任务级测试 → 写入 `_Outputs/待审核/`
**每个模块闭环：** 模块所有任务完成后 → Claude 跑模块级集成测试
**项目完成后：** 跑全量整体测试

Hermes 代码审查（风格、测试覆盖、需求覆盖、安全）。

### 阶段 5：你审核代码产出
🟢 通过 → 合入主项目 → 进入下一任务
🔴 驳回 → 附修改意见 → Hermes 修改任务卡 → 退回 `_Tasks/待执行/` → Claude 重做 → 你再审

### 阶段 6：重复直到项目完成 → 归档

## Bug 修复流程

Bug发现 → Hermes 记录（描述/复现/影响/严重程度）
→ Hermes 分析根因 + 出修复方案（1~2种，含优缺点）
→ 你审核方案（采纳/暂不修）
→ 采纳则写修复任务卡 → Claude 修复 + 测试
→ 你决定是否合入

## 触发方式

**仅在 Hermes 桌面使用**，不走微信。当用户提出开发需求时（如"帮我做个XXX"、"我想开发一个XXX"），自动进入阶段1。

开发相关审批（架构方案、模块产出、Bug方案）也直接在桌面对话中完成，不需要额外命令。

微信仅处理快捷操作：采集、查状态、日常任务。开发全流程在 Hermes 桌面聊天窗口进行。
