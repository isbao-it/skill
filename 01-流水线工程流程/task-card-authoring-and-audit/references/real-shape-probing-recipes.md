# 探针配方：外部平台形状与「有没有料」

服务于 `task-card-authoring-and-audit` §五。两类探针，都**只读**：不写库、不建任务、不落业务记录，
只发少量只读请求（受项目既有的速率闸/公网校验/熔断策略保护）。

## 一、形状探针（出卡前钉真实值）

目的：把卡面要声明的字段从"以为的"换成"实测的"。

只打印形状，绝不打印签名 query 或正文原文：

```
协议 / 主机 / 端口
字段是否存在（含嵌套路径）
字段类型（数字 vs 字符串）
单位与来源（秒 vs 毫秒；条目自带 vs HTTP 头 vs 顶层）
条数（例如一个列表实测有几项——别假设恰好 1）
HTTP 响应头关键项（Content-Type 等），与条目自带的类型字段分开记录
正文前 4 字节魔数
```

经验：**每个"想当然的 1"都可能是 N**（实测音轨 3 条、媒体端口非 443、时长字段不存在只在别处、
下载头与条目声明的类型不一致）。探针脚本落 scratch 或项目工具目录，跑完把实测值直接贴进派工单。

## 二、产粮探针（判断某领域值不值得采集）

输出固定六项，**双采样**：

```
候选上限（结果总数 / 分页上限 / 每页条数）
规模分布         ← 用默认（综合）排序采样
时间分布         ← 同上
时长分布         ← 同上
头部条目 TopN    ← 用按指标排序采样（order=click 之类）
一句结论（有料 / 长尾 / 没料）
```

**双采样是必须的**：只用"按被测量排序"的采样测分布，会得到 `≥100万 = 40/40` 这种单桶输出——
排序本身就把样本压到同一档，看不出真实构成。默认排序看构成、指标排序看天花板，两者合起来才能下结论。

顺带产出：排序参数本身是否匿名可用（有的平台支持多种 `order`），这直接决定卡面要不要加排序开关。

## 三、交付给用户的探针脚本

- 做成**用户能自己重跑**的入口（配一个 `.ps1` 包装，按本机 PowerShell 习惯加 UTF-8 BOM，
  否则中文注释会让脚本解析崩溃，见 `windows-hermes` 技能）。
- 帮助文本要给可复制示例（有的 CLI 不接受 `--help`，要手动处理）。
- 探针与"真采集"命令分开：探针**不写库**，这点要在脚本注释和输出里写明，用户才敢随手跑。
